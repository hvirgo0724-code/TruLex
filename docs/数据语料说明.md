# 数据语料说明

本文档说明途律 · TruLex的知识库语料构成、数据来源、结构规范与入库方式。

## 一、语料总览

语料由 `backend/scripts/generate_rag_data.py` 生成，输出至 `backend/rag_data/`，当前规模：

| 数据类型 | 数量 | 用途 | 落库目标 |
|---|---|---|---|
| 法条（statute） | 52 条 | 法规条文检索、责任认定依据 | Milvus + Neo4j（Law 节点） |
| 判例（case） | 24 条 | 类案检索、裁判规则参考 | Milvus + Neo4j（Case 节点） |
| 术语概念（knowledge） | 20 条 | 法律概念解释 | Milvus + Neo4j（Concept 节点） |
| 图关系 | 530 条 | 法条—案由—判例关系联想 | Neo4j |

| 领域 | 主要法规 | 判例/场景 |

## 三、数据结构规范

### 3.1 法条（`rag_data/milvus/statutes.jsonl`）

每行一个 JSON：

```json
{
  "doc_id": "law-001",
  "title": "《民法典》第832条",
  "text": "承运人对运输过程中货物的毁损、灭失承担赔偿责任...",
  "source_type": "statute",
  "law_name": "民法典",
  "article": "第832条",
  "category": "运输合同",
  "domain": "公路货运"
}
```

### 3.2 判例（`rag_data/milvus/cases.jsonl`）

```json
{
  "doc_id": "case-001",
  "title": "某物流公司公路货物运输合同纠纷案",
  "text": "案情+裁判要旨...",
  "source_type": "case",
  "court": "北京市通州区人民法院",
  "cause": "公路货物运输合同纠纷"
}
```

判例为**匿名化示范性案情**（隐去当事人真实名称，保留真实裁判要旨与法条依据），源自公开判例的裁判规则提炼，覆盖 7 个案由。

### 3.3 术语概念（`rag_data/milvus/knowledge.jsonl`）

```json
{
  "doc_id": "kp-001",
  "title": "货损货差",
  "text": "货损货差是指货物在运输过程中发生的毁损、灭失、短少等损失...",
  "source_type": "knowledge",
  "category": "concept"
}
```

### 3.4 图节点与关系（`rag_data/neo4j/`）

- `nodes.jsonl`：`{"id","type","name","props"}`，type ∈ {Law, Case, Concept, Court, Cause, ORG, MONEY, Vehicle}
- `relations.jsonl`：`{"src_type","src_name","rel","dst_type","dst_name"}`，rel ∈ {CITES, INVOLVES, TRIED_BY, RELATES_TO, MENTIONS}

关系语义：

| 关系 | 方向 | 含义 |
|---|---|---|
| CITES | Case → Law | 判例援引法条 |
| INVOLVES | Case → Cause | 判例涉及的案由 |
| TRIED_BY | Case → Court | 判例的审理法院 |
| RELATES_TO | Concept → Law | 概念关联法条 |
| MENTIONS | Case → ORG/MONEY/VEHICLE | 判例提及的组织/金额/运输方式 |

## 四、数据来源

条文内容整理自现行公开法律法规文本：

- 《中华人民共和国民法典》(2021 施行) 第三编第十九章运输合同
- 《中华人民共和国道路运输条例》(2023 修订)
- 《快递暂行条例》(2025 修订)
- 《中华人民共和国邮政法》
- 《中华人民共和国海商法》(2025 修订)
- 《中华人民共和国铁路法》
- 《中华人民共和国民用航空法》(2026 施行)
- 《危险货物道路运输安全管理办法》(2020 施行)

判例裁判要旨源自公开裁判文书与典型案例报道。

## 五、入库流程

```bash
# 1. 生成结构化语料
docker compose exec -T backend python scripts/generate_rag_data.py

# 2. 入库向量库（Milvus，BM25 + 稠密向量混合检索）
docker compose exec -T backend python scripts/ingest_milvus.py

# 3. 入库图库（Neo4j）
docker compose exec -T backend python scripts/ingest_neo4j.py
```

> 宿主机直连验证可执行 `python scripts/verify_rag_local.py`（需先启动 Milvus/Neo4j 容器并安装本地依赖）。

## 六、数据维护建议

1. **扩充法条**：在 `generate_rag_data.py` 的 `LAWS` 列表追加，字段与现有条目保持一致。
2. **扩充判例**：在 `CASES` 列表追加，`text` 需内嵌法条引用（《...》第X条）、金额、法院、案由，便于实体与关系抽取。
3. **扩充概念**：在 `CONCEPTS` 列表追加，`related_laws` 字段用于生成概念—法条关联关系。
4. **重新入库**：修改后重跑第 1-3 步；若法条/判例去重有变，建议先 drop Milvus collection（`release()` + `drop()`）再重新入库，避免重复向量。
