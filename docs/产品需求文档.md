## 1. 产品概述

### 1.1 产品定位

面向**物流企业、货运/快递经营者、托运人/收货人、法务与律所**的**途律 · TruLex平台**。以「领域法律知识库（Milvus 稠密 + BM25 稀疏混合检索 + Neo4j 法条关系图）+ LangGraph 多 Agent 编排 + 可替换 LLM」为核心，提供智能对话、运单/运输合同审查、货损货差责任认定、物流法规/判例检索、物流法律文书生成等能力，并以合规风控 Agent 与审计体系保障输出可信与安全。

### 1.2 背景与痛点

| 痛点 | 说明 |
|---|---|
| 运输纠纷高频 | 货损货差、快件丢失、延误、运费拖欠、超限超载等纠纷量大，专业咨询成本高 |
| 法规体系分散 | 民法典运输合同章、道路运输条例、快递暂行条例、海商法、铁路法、民航法、危险货物管理办法等分散于多部法律，缺乏统一入口 |
| 通用大模型不可信 | 幻觉引用错误法条、越权给出法律结论、缺乏出处，无法用于责任认定 |
| 责任认定专业性强 | 承运人免责事由、赔偿限额、保价/未保价规则因运输方式而异，需精准引用 |

### 1.3 产品目标

- **可信**：回答基于可检索的法条/判例，必附引用来源，杜绝无源结论。
- **专业**：覆盖公路货运、快递寄递、铁路、航空、水运海商、仓储、多式联运、危险货物运输等全领域。
- **安全合规**：合规风控兜底 + 内容安全 + 全程审计留痕。
- **可运营**：知识库可迭代入库，模型可微调（PT/SFT/DPO），有评测门禁与灰度发布。

### 1.4 目标用户

| 角色 | 说明 |
|---|---|
| 物流/货运企业 | 运单审查、货损责任研判、合规咨询、风险提示 |
| 快递/寄递经营者 | 快件丢失延误赔偿、验视义务、保价规则咨询 |
| 托运人/收货人 | 维权咨询、责任认定、索赔文书草拟 |
| 企业法务/律所 | 类案检索、法条核验、运输合同草拟与审查 |
| 运营/管理员 | 知识库维护、审计、模型发布 |

### 1.5 产品价值

通过「检索增强 + 合规兜底」提升大模型在物流交通法律场景的可信度，降低运输纠纷的法律咨询边际成本，助力企业合规经营与高效维权。

| 角色 | 权限 |
|---|---|
| 游客 | 仅登录页 |
| 普通用户 | 智能对话、运单审查、法规/判例检索、货损责任认定、文书生成、查看个人会话 |

### 3.2 FR-AUTH 用户认证

- 描述：用户名/密码登录与注册，签发 JWT；首次启动自动种子默认管理员。
- 验收：登录返回 `access_token`；`POST /api/v1/auth/register` 注册普通用户；未登录访问受保护接口返回 401；`GET /api/v1/auth/me` 返回当前用户。

### 3.3 FR-CHAT 物流法律智能对话

- 描述：客服对话流，多轮上下文，**真流式（SSE）逐 token 输出**，回答附法条/判例引用。
- 关键点：
  1. 支持新建/继续会话，历史消息持久化（MySQL）。
  2. **真流式实现**：后端 `ChatOpenAI(streaming=True)` + contextvars/`asyncio.Queue` token 管道，生成节点逐 token `emit_token`，`stream_chat` 边跑图边消费队列实时回传；首 token 约 1 秒到达，逐字输出。
  3. 主控 Agent（supervisor）依据意图路由到运单审查/法规检索/判例检索/货损责任认定/文书生成/通用问答。
  4. 所有回答经合规风控 Agent（compliance_guard）兜底（越权结论拦截 + 免责提示 + PII 脱敏）。
- 验收：输入物流法律问题 → 流式返回 + 引用脚注；`GET /api/v1/chat/history` 可拉取历史。

### 3.4 FR-WAYBILL 运单/运输合同审查

- 描述：上传 `.docx`/`.pdf`/`.txt` 或粘贴运输合同/运单文本，识别风险条款并高亮。
- 接口：`POST /api/v1/contract/review`（`multipart/form-data`：`text`/`title` + `file`）。
- 输出：`{items: [{clause, risk_level(high/medium/low), suggestion, highlight}], summary}`。
- 关键点：条款级审查；风险分色高亮；覆盖保价/未保价、赔偿限额、免责、危险货物、超限超载、运费、时效、管辖等物流特有风险。
- 验收：上传/粘贴运单 → 返回风险点列表与可高亮原文片段。

### 3.5 FR-STATUTE 物流法规检索

- 描述：基于 Milvus 稠密向量 + BM25 稀疏向量**混合检索（RRF 融合）**的物流交通法规检索，检索后由 LLM 归纳解读。
- 覆盖：民法典运输合同章、道路运输条例、快递暂行条例、邮政法、海商法、铁路法、民用航空法、危险货物道路运输安全管理办法等（现入库 **56 条法条**）。
- 验收：按关键词精确命中法条号/条文，返回来源、所属法律、领域分类与相关度。

### 3.6 FR-CASE 物流判例检索

- 描述：类案检索，结合 Milvus 混合检索 + Neo4j 法条/案由/运输方式关系图做类案联想，检索后由 LLM 归纳裁判规则。
- 数据：现入库 **32 条真实货运/快递/海商/铁路/航空/多式联运/冷链判例**。
- 验收：按案情描述召回相关运输纠纷判例，并关联适用法条与运输方式。

### 3.7 FR-LIABILITY 货损货差责任认定

- 描述：综合检索法条与判例，由 LLM 分析货物毁损、灭失、短少、延误的责任归属、免责事由与赔偿计算。
- **专属交互页**：前端「货损责任认定」页（`/liability`）提供结构化表单（运输方式/货损类型/是否保价/保价额/货损金额/运费支付/事故经过），自动拼装专业要素描述后走 `/chat` 流式接口，责任分析 + 法律依据引用**逐字流式回显**。
- 验收：输入纠纷事实 → 输出结构化责任认定结论，援引具体法条（如民法典第 832、833 条）并附引用。

### 3.8 FR-DOC 物流法律文书生成

- 描述：生成货物运输合同、货损索赔函、律师函、起诉状等，检索法条作为依据。
- 验收：按模板生成文书并附法条依据；带免责声明。

### 3.9 FR-KB 知识库管理

- 描述：`generate_rag_data.py` 产出结构化语料（法条/判例/概念），`ingest_milvus.py` / `ingest_neo4j.py` 入库向量库与图库；稠密向量化（1024 维）+ BM25 稀疏化，统一写入 Milvus。
- 验收：入库后可通过检索接口命中。

### 3.10 FR-ADMIN 运营后台与审计

- 描述：审计日志查询、指标看板、模型版本管理。
- 验收：`GET /api/v1/admin/audit` 分页返回审计记录；`/metrics` 暴露 Prometheus 指标。

### 3.11 FR-ML 模型训练与发布

- 描述：Unsloth 三阶段（PT/SFT/DPO）→ 评估门禁 → vLLM 推理 → 灰度发布。
- 验收：三阶段脚本可独立运行；评估（自动指标 + LLM Judge + 红队）全过才发版。

## 4. 核心业务流程

### 4.1 对话流（真流式）

```
用户输入 → supervisor(意图路由) → 专业 Agent(运单审查/检索/责任认定/生成)
        → compliance_guard(兜底审查) → 逐 token 流式回传(含引用) → 落审计日志
        ↑ 生成节点经 astream + emit_token 实时推 token 到 SSE
```

### 4.2 运单审查流

```
上传/粘贴 → 解析(docx/pdf/txt) → 条款切分 → 规则扫描 + LLM 增强
         → 风险点 + 高亮 → 合规兜底 → 返回并审计
```

### 4.3 货损责任认定流

```
要素表单 → 拼装专业描述 → 法规检索(混合) + 判例检索(混合+图) → LLM 综合研判(流式)
        → 责任归属 + 免责分析 + 赔偿计算(附引用) → 合规兜底 → 逐字返回
```

### 4.4 知识入库流

```
generate_rag_data.py → 结构化语料(法条/判例/概念 + 图节点关系)
        → ingest_milvus.py(稠密 + BM25 稀疏) + ingest_neo4j.py(关系图)
```

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|---|---|
| 首 token 延迟（流式） | ≤ 3s（P95），实测约 1s |
| 问答完整响应 | ≤ 30s（P95） |
| 检索延迟 | ≤ 500ms（P95） |
| 并发 | 无状态水平扩展支撑 100+ 并发会话 |

> 已知优化项：检索型问题（法条/判例归纳）完整生成仍偏慢（约 1 分钟），已通过流式化缓解体验，可进一步换更快模型或缩短注入上下文。

### 5.2 可用性与可扩展性

- 后端无状态、可水平扩展；容器化部署；中间件健康检查与自动重启。
- LLM 失败有超时与重试；记忆层降级可用（PG 不可用不让应用崩溃）。

### 5.3 安全与合规

- JWT + bcrypt；RBAC；OIDC 扩展。
- 内容安全：合规风控兜底、敏感词、越权结论拦截、免责声明。
- 数据合规：PII 脱敏、文件加密、传输 TLS、日志脱敏。
- 全链路审计留痕。

### 5.4 可观测性

- 日志：structlog JSON → Loki。
- 指标：Prometheus `/metrics` + Grafana。
- 链路：OTel → Jaeger。
- 告警：错误率、P95 延迟、LLM 失败率。

## 6. 验收标准

1. 前后端分离，全栈 `docker compose up -d` 可启动。
2. 用户可登录、发起**真流式**对话并获得带引用的物流法律回答（首 token 约 1s，逐字输出）。
3. 运单/运输合同上传 → 返回风险点 + 高亮。
4. 物流法规检索返回命中列表与来源（法条号、所属法律、领域）。
5. 货损责任认定（专属页）输出援引法条的结论，逐字流式回显。
6. 管理员可查看审计日志。
7. `/healthz`、`/metrics` 正常。
8. 训练三阶段脚本可运行，评估可产出报告，可 vLLM 部署。

## 8. 当前实现状态

截至最新版本，系统已完成全栈闭环并验证通过：

- **知识库**：56 条法条 + 32 条判例 + 20 个概念已入库（Milvus 108 条向量；Neo4j 191 节点 + 618 关系）。
- **多 Agent**：6 路由（waybill/statute/case/liability/document/chat）全链路可用。
- **真流式**：`ChatOpenAI(streaming=True)` + token 管道，责任认定/法规/判例/文书/兜底生成均逐 token 回传。
- **前端**：7 个页面（登录/智能对话/运单审查/货损责任认定/知识检索/审计日志/404），货损责任认定与知识检索均有专属交互页。
- **测试**：26 个单元测试全部通过；前端 `vue-tsc` 类型检查通过。
- **端到端**：经 nginx 代理（8080）实测对话/运单审查/知识检索/责任认定全部正常。
