## 2. 环境准备与快速启动

### 2.1 依赖

Docker + Docker Compose（训练需 NVIDIA 容器运行时 + CUDA 驱动）。

### 2.2 启动

```bash
cd trullex
cp .env.example .env          # 填入 API_KEY 等真实值
docker compose up -d          # 起中间件 + 前后端
docker compose ps             # 查看状态
```

前端访问 `http://localhost:8080`，后端文档 `http://localhost:8000/docs`。

> ⚠️ **env_file 重载坑**：`docker compose restart` **不会**重读 `.env`（环境变量是容器创建时的快照）。修改 `.env`（如更换 `API_KEY`）后必须 `docker compose up -d backend` 重建容器才能生效。

### 2.3 训练（GPU，可选）

```bash
docker compose --profile training build training
docker compose --profile training run --rm training python scripts/train_sft.py
```

## 4. 知识库数据准备与入库

### 4.1 生成结构化语料

```bash
cd backend
python scripts/generate_rag_data.py
```

产出（`backend/rag_data/`）：
- `milvus/statutes.jsonl`  物流法规条文（**56 条**，覆盖 8+ 部法律）
- `milvus/cases.jsonl`     典型运输纠纷判例（**32 条**）
- `milvus/knowledge.jsonl` 物流法律术语概念（**20 条**）
- `neo4j/nodes.jsonl`      图节点（法条/判例/概念/法院/案由/运输方式/组织）
- `neo4j/relations.jsonl`  图关系（援引/涉及/审理/关联/提及）

### 4.2 入库向量库与图库

需先启动中间件，然后：

```bash
docker compose exec -T backend python scripts/ingest_milvus.py
docker compose exec -T backend python scripts/ingest_neo4j.py
```

### 4.3 数据清洗说明

语料中的法条条文整理自现行法律法规公开文本，覆盖：
- **公路货运**：民法典运输合同章、道路运输条例
- **快递寄递**：快递暂行条例、邮政法
- **铁路**：铁路法
- **航空**：民用航空法
- **水运海商**：海商法
- **多式联运**：民法典多式联运合同、海商法多式联运
- **危险货物**：危险货物道路运输安全管理办法、道路运输条例
- **冷链 / 货运代理**：快递延误、冷链生鲜、货运代理判例

每条法条含 `doc_id`、`title`（法条名）、`law_name`（所属法律）、`article`（条文号）、
`category`（分类）、`domain`（领域）、`source_type`、`text`（条文全文），供混合检索与图构建使用。

> 提示：本语料用于产品原型与检索演示，正式法律意见须以官方发布文本为准。

## 5. 后端开发指南

### 5.1 核心约定

- 配置统一从 `app.core.config.Settings` 读取，禁止散落硬编码。
- LLM 一律经 `LLMProvider`（底层 `ChatOpenAI(streaming=True)`），业务代码不直接 `new ChatOpenAI`。
- SQLAlchemy 2.x 风格（`Mapped` / `mapped_column`），业务库 async（aiomysql）。
- 记忆库（DB_URI）与业务库（MYSQL_URL）是**两套独立连接**。
- 检索的同步调用（Milvus/Neo4j）一律经 `loop.run_in_executor` 放入线程池，避免阻塞事件循环。

### 5.2 新增一个工具

1. 在 `app/agents/tools.py` 定义函数，返回结构化结果。
2. 注册到 `TOOLS` 字典。
3. 在 `app/agents/nodes.py` 对应节点中调用。

### 5.3 新增一个 Agent 节点

1. 在 `app/agents/nodes.py` 写节点函数（接收 `state`，返回 `dict` 更新），并注册到 `NODES`。
2. 在 `app/agents/graph.py` 中 `add_node` 并接入 `compliance_guard` 之前。
3. 在 `_route_after_supervisor` 的映射表增加路由标签。
4. 若需流式输出，节点内用 `llm.astream(...)` 逐 chunk `emit_token(token)`。

### 5.4 扩展领域知识

1. 在 `backend/scripts/generate_rag_data.py` 的 `LAWS` / `CONCEPTS` / `CASES` 中增补条目。
2. 在 `app/retrieval/extraction.py` 的 `CONCEPT_LIST` / `CAUSE_LIST` / `VEHICLE_LIST` 增补领域词典。
3. 重新运行 `generate_rag_data.py` 并重新入库。

### 5.5 新增一个 API 接口

1. 在 `app/schemas/` 定义 Pydantic 请求/响应。
2. 在 `app/api/` 对应模块写路由（依赖 `get_db` / `get_current_user`）。
3. 在 `app/api/router.py` 注册。

## 6. 前端开发指南

### 6.1 本地开发

```bash
cd frontend
npm install
npm run dev        # Vite 代理 /api → http://backend:8000
```

### 6.2 SSE 对接

`src/api/chat.ts` 用 fetch + `ReadableStream` 按 `\n\n` 分帧解析 `data:`，**事件格式**：

| 事件 | 数据 | 说明 |
|---|---|---|
| `token` | `{"content":"..."}` | 逐 token 增量文本 |
| `citations` | `{"items":[...]}` | 末尾引用脚注 |
| `done` | `{"conversation_id":..., "route":...}` | 流结束 |
| `error` | `{"message":"..."}` | 处理失败 |

token 以 `Authorization: Bearer` 手动注入（fetch 不走 axios 拦截器）。

> 注意：前端消费的是 `event: token` 的 `content` 字段，**不是** `delta`；`citations` 从 `items` 解包。

### 6.3 新增页面

1. 在 `src/views/` 建视图。
2. 在 `src/router/index.ts` 注册路由（受保护路由需鉴权守卫）。
3. 需要接口则在 `src/api/` 增加方法，类型写入 `src/types/index.ts`。
4. 侧边栏菜单在 `src/components/AppLayout.vue` 增项。

## 8. API 接口文档

前缀 `/api/v1`。

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/auth/login` | 登录，返回 access_token | 否 |
| POST | `/auth/register` | 注册新用户（角色 user），返回 access_token | 否 |
| GET | `/auth/me` | 当前用户 | 是 |
| POST | `/chat` | SSE 流式问答（含运单审查/责任认定/检索路由） | 是 |
| GET | `/chat/history` | 会话历史 | 是 |
| POST | `/contract/review` | 运单/运输合同审查（multipart：`text`/`title` + `file`） | 是 |
| POST | `/knowledge/search` | 物流法规知识检索（返回 `{hits:[...]}`） | 是 |
| POST | `/documents/upload` | 上传入库（Celery 异步） | 管理员 |
| GET | `/admin/audit` | 审计日志 | 管理员 |
| GET | `/healthz` | 健康检查 | 否 |
| GET | `/metrics` | Prometheus 指标 | 否 |

> 完整接口细节（参数、响应体、SSE 事件、curl 示例）见《API 接口文档》。

### 8.1 登录与注册示例

系统首次启动会自动创建默认管理员 `admin` / `admin123456`（角色 admin），可直接登录；也可通过注册接口创建普通用户（角色 user）。

```http
POST /api/v1/auth/login
Content-Type: application/json

{"username":"admin","password":"admin123456"}
```

注册：

```http
POST /api/v1/auth/register
Content-Type: application/json

{"username":"alice","email":"alice@example.com","password":"secret123"}
```

响应：`{"access_token":"...","token_type":"bearer"}`

### 8.2 流式问答（SSE）

```http
POST /api/v1/chat
Authorization: Bearer <token>
Content-Type: application/json
Accept: text/event-stream

{"message":"货物运输途中毁损，承运人要承担赔偿责任吗？"}
```

事件流（真流式，逐 token）：

```
event: token
data: {"content":"## 一、承运人是否承担赔偿责任..."}

event: token
data: {"content":"..."}
...（逐 token 持续输出）...

event: citations
data: {"items":[{"source":"statute","title":"《民法典》第832条","snippet":"..."}]}

event: done
data: {"conversation_id":"...","compliance_ok":true,"route":"liability"}
```

### 8.3 运单审查（multipart）

```http
POST /api/v1/contract/review
Authorization: Bearer <token>
Content-Type: multipart/form-data

--boundary
Content-Disposition: form-data; name="text"

货物运输合同条款...
--boundary
Content-Disposition: form-data; name="file"; filename="contract.docx"
Content-Type: application/octet-stream

<binary>
--boundary--
```

响应：`{"items":[{"clause":"...","risk_level":"high","suggestion":"...","highlight":"..."}],"summary":"共发现 N 处风险点。"}`

> ⚠️ 该接口接收 `multipart/form-data`（`text`/`title`/`file` 表单字段），**不是** JSON body。

### 8.4 知识检索

```http
POST /api/v1/knowledge/search
Authorization: Bearer <token>
Content-Type: application/json

{"query":"快递丢失赔偿标准","top_k":5}
```

响应：`{"hits":[{"score":0.9,"source":"statute","text":"...","title":"《快递暂行条例》第28条","metadata":{...}}]}`

## 11. 常见问题排查（FAQ）

| 问题 | 原因与解决 |
|---|---|
| 记忆层启动失败导致崩溃 | `enter_memory` 已做降级（返回 None），确认 PG 健康后重启 |
| `PostgresSaver` 连接报错 | 已自动把 `postgresql+psycopg2://` 规整为 `postgresql://`；确认 `DB_URI` 值正确 |
| LangGraph 版本签名不匹配 | 当前锁定 LangChain/LangGraph 1.x 组合：`langchain==1.4.6`、`langgraph==1.2.19`、`langgraph-checkpoint-postgres==3.2.0` |
| Milvus 维度不一致 | 建 collection 维度必须等于 `EMBEDDING_DIM=1024`，改模型需重建 collection |
| Milvus 重复向量 | 用 `release()` + `drop()` 彻底清理后重跑 `ingest_milvus.py` |
| 对话/责任认定「一直转圈」 | 确认 `ChatOpenAI` 已设 `streaming=True`；否则 `astream` 退化为一次性 `ainvoke` 后切块，前端无中间反馈 |
| 前端 SSE 无流式输出 | nginx 需 `proxy_buffering off`；确认后端 `/chat` 返回 `text/event-stream` |
| 知识检索「黑屏」 | 后端返回 `{hits:[...]}`，前端需解包 `data.hits`，不能当数组直接遍历 |
| 运单审查「请提供合同文本」 | 接口接收 `multipart/form-data`（`text`/`title`/`file`），前端用 FormData 提交，别发 JSON body |
| 修改 `.env` 后不生效 | `docker compose restart` 不重读 env_file，需 `docker compose up -d backend` 重建容器 |
| 镜像名带双横线 | compose 项目名取自目录名，目录含中文/空格时镜像名异常，用 `docker compose build` 重建 |
| 登录无账号 | 首次启动自动种子默认管理员 `admin`/`admin123456`，或走 `POST /auth/register` 注册普通用户 |
| aiomysql 登录报 `ping() missing 'reconnect'` | `create_async_engine` 已去掉 `pool_pre_ping`（aiomysql 0.2.0 兼容）；靠 `pool_recycle=3600` 回收连接 |
| LLM 调用失败 | 检查 `API_KEY`/`BASE_URL`/`MODEL_NAME`；有 tenacity 重试，失败会落审计 |
| 知识库为空 | 先 `generate_rag_data.py` 生成语料，再 `ingest_milvus.py` / `ingest_neo4j.py` 入库 |
